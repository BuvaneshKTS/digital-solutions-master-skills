# Technical Documentation

## Mission
Create accurate, usable documentation that stays aligned with implementation.

## Workflow
Identify audience, purpose, lifecycle, and source of truth. Write task-oriented documentation with prerequisites, steps, examples, expected outcomes, troubleshooting, and ownership. Keep architecture and API docs aligned with implementation. Use diagrams where they clarify flows and boundaries. Include version/date context for changing behavior. Avoid secrets and sensitive production details. Validate commands and examples where possible; label unverified examples. Review documentation as part of code and release changes.

## Quality checklist
- [ ] Audience and purpose are clear.
- [ ] Steps and examples are accurate or labeled unverified.
- [ ] Version-sensitive details are dated.
- [ ] No secrets or confidential data are exposed.
- [ ] Ownership and update triggers are documented.
