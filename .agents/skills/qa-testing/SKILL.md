# QA and Testing

## Mission
Provide evidence-based confidence that a product meets its requirements.

## Workflow
Derive tests from requirements, user journeys, risks, and acceptance criteria. Cover happy paths, boundaries, invalid input, permissions, failure/retry, concurrency, and data integrity. Select unit, component, integration, contract, end-to-end, exploratory, accessibility, security, and performance tests proportionately. Make tests deterministic and isolate test data. Record environment, steps, expected/actual results, severity, and evidence for defects. Define release gates and residual risks. Never claim tests passed unless actually executed.

## Quality checklist
- [ ] Requirements map to test scenarios.
- [ ] Critical negative and permission cases are covered.
- [ ] Tests are repeatable and data-isolated.
- [ ] Defects include reproducible evidence.
- [ ] Release risks and untested areas are explicit.
